# 招聘数据采集与本地接入

默认目标项目：`D:/2026/2026product/offerflow`。
默认交付页面：`http://127.0.0.1:5180/job-discovery.html`。
这是本地文件和本地服务，不是云端发布。用户另指定项目或地址时跟随用户。

## 开始

读取项目的 AGENTS.md（如有），以及本技能的 [字段规范](references/schema.md) 和 [页面接入](references/integration.md)。检查现有页面和数据结构，延续用户已确定的格式。用户给出的入口决定采集范围：校园入口不要擅自扩大到全站，混合入口默认全部收录并保留校招、实习、全职分类；简短说明范围即可，不重复确认已授权的采集和本地接入。

## 选择采集方式

1. **先验证程序化方式。** 打开官方入口，查看页面实际内容、分页、筛选和一条岗位详情。优先静态 HTML、页面内嵌结构化数据、官网公开 API；动态网站可用浏览器观察正常点击产生的网络响应。接口地址、参数、岗位 URL 应从真实页面和请求中取得，不猜接口、令牌或详情链接。
2. **有完整、稳定结果就程序化采集。** 对照官网验证标题、岗位 ID、正文、工作地点、类型、发布时间和总数；验证下一页不重复第一页、列表返回的是全文还是摘要。列表缺少内容时读取详情。可用官方 API、HTTP 客户端或浏览器自动化；不强制为了形式使用 dokobot。
3. **程序化无法可靠取得数据就用 dokobot CLI。** 例如请求被拒、JS 页面内容缺失、接口不稳定、需要用户现有浏览器状态，或只能得到摘要。经一次有针对性的修正仍无实质进展就切换，不反复空转。可混合“程序化枚举列表 + dokobot 读详情”。切换只改变获取方式，不降低字段和覆盖要求。
4. 遇到登录、验证码或明确访问限制，不绕过；dokobot 使用用户正常可见的页面。若仍受阻，保存已完成结果、列出未完成范围和所需操作，不能宣称全量完成。

### dokobot CLI 回退

进入回退分支时读取已安装的 dokobot 技能（当前在 `C:/Users/Administrator.DESKTOP-1OBI06T/.agents/skills/doko/SKILL.md`；若路径变化从技能目录查找），以实际 CLI 帮助为准：

```powershell
dokobot --version
dokobot read --help
dokobot read '<实际官网URL>' --local
```

优先 `--local`，使用本机 Chrome、扩展及 bridge；本地模式无需 API key。不要因为缺少远程 key 要求用户配置云端。根据帮助使用 `--timeout`、`--screens`；返回 `canContinue` / `sessionId` 时继续读取，直到正文完整。并发从低值开始，最多 5 个读取任务，遇限流降低并发。保存每条原始输出和来源 URL；不要把页面导航、登录提示或占位符当 JD。读取不是自动分页：枚举所有页、加载更多和详情链接，必要时配合正常浏览器交互。仅关闭本次创建的读取会话。dokobot 不可用时说明具体缺失依赖，不假装已经调用。

## 整理与核验

### 公司标识核验

- 页面接入前为每个公司建立明确的品牌标识映射；不要把公司名称文字、首字母或另一家公司的 Logo 当作目标公司的标识。
- 优先使用公司官网或招聘官网可核验的品牌标识；若没有稳定、可再分发的官方图片资源，使用与品牌色一致的无版权文字徽章，并通过 `aria-label` 保留公司全名。
- 新增公司后，在岗位列表卡片、岗位详情和公司页分别检查标识，确认没有复用其他公司的样式类。标识问题修复后，把映射和样式一并写回页面实现，不能只改当前截图或单条数据。
- 采集输出无需保存未经核验的 Logo URL；品牌标识属于页面展示层，岗位数据只保存公司名称和来源链接。

- 输出到项目 `outputs/<company>-<YYYY-MM-DD>/`：`jobs.json`、`jobs.jsonl`、可读 Markdown 全文、`validation.json`、原始列表及详情证据和本次采集脚本。日期用本次实际日期，原始响应只保留与公开岗位有关的内容，排除 cookie、凭据和无关个人数据。
- 每岗一条；完整正文合并为 `jd`，去除条目行首序号但保留段落、小标题、资格、加分项及部门介绍。不要按职责序号拆岗位，不只留下摘要。
- 学历、专业必须是简洁规范值，保留“优先、在读、不限”等条件；没有证据为 null。“计算机领域发表论文”不能提取成“计算机专业要求”。完整原文可追溯。
- 发布时间只用官网明确的发布时间或已核实的首次发布字段。不得用采集、核验、更新、内部创建日期替代。缺失显示“未公布”。招聘类型不能只靠职位名猜；优先官网分类、筛选与详情证据。
- 核对官网总数、分页覆盖、唯一岗位数、详情完整性和字段缺失。官网分页可能重复或动态变化：按公司和源 ID 去重，补查漏项，保留每轮证据；数量相等也要检查集合与正文。无法对齐时如实报告差异。
- 可运行 `python <技能目录>/scripts/validate_jobs.py <jobs.json> --expected <预期条数>` 检查结构；它不代替官网证据核验。
- 用户要求 Excel 时沿用每岗一行格式并使用已安装的表格技能生成与检查；未要求时优先完成本地页面接入，不为了额外文件耽误交付。

## 接入与交付

按 [页面接入](references/integration.md) 合并现有数据，更新公司展示、类型、发布时间和来源链接，恢复本地服务并在真实浏览器验证。保留原有公司、收藏和投递记录；不因新增公司覆盖其他数据。不止生成文件就停止，也不擅自发布到公网。

最终简短报告新增/合计数量、实际采集方式（程序化、dokobot 或混合）、发布时间缺失情况，并给出可点击的本地页面地址。只有浏览器验证页面已加载新数据后才称“已接入”。
