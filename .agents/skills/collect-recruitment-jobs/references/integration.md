## 数据合并

在写入前保存现有数据快照到本次 outputs。验证新数据后，以公司 + 源岗位 ID 做幂等更新和新增，保留其他公司与未知扩展字段；新批次有缺项时不覆盖成更差数据，除非有明确的新官网证据。不要把校招子集当作公司全量快照删除实习/全职。先写临时文件并验证，再替换页面 JSON。

主页面当前使用 `typeof source[number]` 推导类型。新增公司带来的 null 字段、可选字段、数组形状应处理好，筛选选项不显示空白；新增通用字段要为旧记录补 null 或可靠值，不补猜测值。

检查 `source_job_id` 是否跨公司冲突。没有冲突则保留旧 ID 和 URL，已有收藏继续有效。有冲突时引入稳定公司限定键，更新选择、列表 key、收藏、投递、URL 参数；用旧公司上下文迁移可明确归属的旧 ID，含歧义的记录保留并标明，不能错配。

## UI 必须体现新数据

- 公司、城市、方向、学历、招聘类型筛选从实际数据生成；保留现有布局和交互。
- 每张岗位卡片和详情显示正确公司、招聘类型、发布时间。未公布日期显示“未公布”，而非采集日期；ISO 时间按 Asia/Shanghai 展示，只有日期的字符串不做时区转换。
- “最新发布”按真实发布日期降序，缺失日期排最后。核验时间独立显示。
- 公司与招聘页的名称、方向数量、入口和规则按公司决定，不能将小红书的投递规则复用给新公司。
- 官网投递使用 application_url，可读原文使用 detail_url；不要打开投递链接执行真实投递。
- 更新帮助文字和统计，不把历史固定总数和采集日期硬编码到新数据；有薪资、项目等已披露字段时可展示，不伪造缺失项。

## 启动与验证

先检查 5180 是否已有目标服务；能访问则复用，Vite 通常会自动更新数据。端口被其他服务占用时不要杀进程或悄悄换地址。服务未运行时，在 `apps/web` 启动：

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5180 --strictPort
```

使用可持续运行的工具会话，或 Windows `Start-Process -WindowStyle Hidden` 并记录日志。一次启动输出不证明进程持续存活，结束前重新确认地址可访问。只启动本地服务，不部署公网。

运行 `pnpm --filter @offerflow/web typecheck`。用可用浏览器/Playwright 检查实际页面而非只查 HTTP 200：

- 总数、目标公司数量、招聘类型数量与验证报告一致；旧公司仍在。
- 选择一条新岗位核对公司、完整 JD、日期、类型及官网链接；未知发布日期展示正确。
- 公司/招聘类型筛选可组合，“最新发布”排序正确，刷新后已有 URL 筛选仍工作。
- 无浏览器页面异常；桌面和手机截图检查标签、日期、筛选及正文不被挤出或遮挡。
- 若改过键，检查已有收藏和投递标记的迁移；一般不需要为简单样式变更新建测试框架。

最终给页面链接，可附 `?company=<URL编码公司名>`。说明这是本机数据与本地预览，不称作云端发布。若服务不可用或数据仅部分接入，准确说清未完成部分。
